# 视觉编码与 Prefill 拆步：A 阶段结果与门槛结论

日期：2026-11-07  
实验运行：`vl-stage-split-20261106-191642`  
方案：[视觉编码与Prefill拆步实验方案.md](视觉编码与Prefill拆步实验方案.md)

## 阶段结论

**本轮停止在 A 阶段门槛，B、C 未执行。** 三组默认配置数据都重现了明显的 R−T 文本间隔差异，缓冲式打点也能把客户端长间隔与 engine token、API yield、混合 scheduler 步对齐。但没有一套 probe-on 采集配置在 T、R 两臂同时满足预设开销上限，因此当前不能把这组插桩数据作为通过 A 的证据，也不应据此推进拆步实现。

这不是对“拆步机制无效”的反证。它表示本轮在机制实验前，尚未得到满足误差门槛的观测方法；研究假设仍未判定。

## Probe 开销门槛

开销按每臂 probe-off 与 probe-on 的 pooled episode P95 绝对差计算；允许值为 `max(1 ms, probe-off P95 的 5%)`。

|采集组|臂|off P95 (ms)|on P95 (ms)|绝对差 (ms)|允许差 (ms)|通过|
|---|---|---:|---:|---:|---:|---|
|初始 SSD 缓存组|T|5.342|5.903|0.562|1.000|是|
|初始 SSD 缓存组|R|29.423|23.864|5.559|1.471|否|
|buffered128|T|5.326|7.016|1.690|1.000|否|
|buffered128|R|24.219|23.716|0.503|1.211|是|
|buffered512|T|5.450|5.522|0.072|1.000|是|
|buffered512|R|24.761|29.714|4.953|1.238|否|

把事件刷新批量从 128 提高到 512 后，T 臂差值降至 0.072 ms，R 臂差值却达到 4.953 ms。初始轻量配置、buffered128 和 buffered512 各自在不同臂失败；因此没有一组完整配对同时通过 T、R 的探针门槛。变化可能包含批量写盘、负载顺序或运行间波动，当前证据不足以把差异唯一归因于其中一种原因。

Eager 单列：轻量探针 T 臂绝对差 3.634 ms（允许 1 ms，失败），R 臂 0.247 ms（允许 1.682 ms，通过）。eager 不是本阶段常用部署配置的放行依据。

## 缓冲式时间线核对

buffered128 与 buffered512 各有 32 个 probe-on 测量 episode，验证错误均为 0。客户端事件覆盖 24,576 个文本输出 token 和 256 个图文输出 token。engine-ready 与 API-yield hook 覆盖文本 `/v1/completions` 路径：每组 128 个正式文本请求的完整 token ID 序列均与客户端逐项一致；另有诊断回放记录。图文 chat 输出及 TTFT 保留在客户端 SSE 中，本轮没有在 chat API 路径打 engine/API token hook。两组的 16/16 个 R episode 均找到首个混合 scheduler 步和视觉 forward；最大文本间隔两端均完成 engine/API/client token ID 对齐，16/16 序号对应 token 一致。

buffered128 的代表 episode `A-default-probe1-buffered-probe1-1-R-07`，所有时间相对 episode anchor：

|事件|相对 anchor (ms)|
|---|---:|
|首个图文混合 scheduler 步（图文 595 token、四路文本各 1 token）|14.247|
|visual forward 起点|15.400|
|最大间隔左侧 engine-ready / API yield / 客户端 SSE|26.888 / 26.904 / 27.260|
|最大间隔右侧 engine-ready / API yield / 客户端 SSE|50.767 / 50.779 / 51.127|
|三处测得的 token 间隔 (ms)|23.879 / 23.875 / 23.867|

这条时间线说明长间隔已出现在 engine 输出侧，不是单纯客户端 SSE 或 API 序列化尾部的延迟。buffered512 中 visual forward 早于该 episode 最大间隔的有 9/16 个；其他 episode 的 visual forward 落在间隔内或更晚。因此应保留“混合调度步与长间隔有稳定时间关联”的结论，不把所有间隔都简化为“视觉前向完整覆盖了停顿”。

## 实验执行与归档

- 正式可比测量共 256 个 episode：原计划 128 个，加两组 buffered 复测各 64 个。另保留 eager heavy 探索组和首次缓存落到 home 的 65 个 episode，作为排除数据，不纳入门槛计算。
- 实验只使用 GPU0；负载中核对为 PCIe Gen4 ×16。GPU1 保持空闲（约 45 MiB）。模型、数据集、权重快照、事件/资源日志和新建 GPU 编译缓存位于 `/media/chx/Win10` 的 SSD 目录。原四格结果 JSON 当时写入独立 project 目录，已复制进本地完整归档；两组 buffered 结果 JSON 直接写在 SSD。原环境和原项目未改动。
- 按服务启动至确认释放保守累计约 1,031 秒（17.2 GPU 分钟），低于 A 阶段 25 分钟及总计 120 分钟上限。所有完成单元退出后 GPU0 回到 782 MiB，8271 端口关闭。一次 preflight 因 `nvidia-smi -q -d PCI` 参数不兼容而在服务启动前失败，没有占用 GPU，已在账本中保留并修正命令。
- 原始 JSON、SSE、scheduler、engine/API 事件、资源采样、PCIe 状态、命令与补丁均保留在 [本地运行归档](../../reproduction_runs/vl-stage-split-20261106-191642/)。核心复算见 `results/A-analysis.md`、`results/A-buffered128-analysis.md`、`results/A-buffered512-analysis.md`；代表时间线分别存于对应 JSON。

## 下一步的最小补证

先改用异步批量写盘或 ring buffer，将记录线程与 API/engine 服务路径隔离；再以 T/R 反序和交错顺序各复测一个配对块，提前固定“记录线程队列深度、丢失计数、完成时排空”指标。若同一 probe 版本在 T、R 两臂都通过开销门槛，并复现两块 R−T 差异，才重新打开 A 并进入 B。若轻量异步采集仍无法通过，就先停止这个测量切口，不投入拆步实现或 C 阶段扫参。
