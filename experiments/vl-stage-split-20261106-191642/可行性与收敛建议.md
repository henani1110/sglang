# 单卡图文混跑的研究可行性与下一轮决策

2026-11-06 · 复核 Qwen3-VL-2B-Instruct / vLLM 0.33.0 的双 4090 pilot

**建议继续一轮，先验证固定预算的失效边界。** 把研究问题收敛到：同一张 GPU 上，在途文本的下一 token 有截止时间，待进入的图文请求也有首 token 截止时间。当视觉编码和图文 prefill 合在一个迭代会造成停顿时，把两段安排到相邻迭代、在中间推进文本 decode，能否同时守住两类请求的目标？进一步，能否用当前批次的可用时间决定何时同迭代执行、何时拆开，且比充分调优的固定规则多完成达标请求？

这个问题可以复用现有 GPU0、模型和插桩，首轮只涉及阶段观测与一次时序干预。原有实验给出了可重复的停顿；部署配置下的影响、固定策略的失效范围和选择性拆分的收益都待验证。通用的视觉干扰、视觉与 LM 解耦、双预算、SLO 感知的分块均已有直接先例。

## 3. 收敛到一个调度决定

保留单卡单实例、原图和模型输出路径，只改变同一图文请求的视觉编码 E 与首个 LM prefill P 是否进入同一迭代。最小实验比较同迭代的 `E → (P+D)` 和错开的 `(E → D) → (P+D)`，其中 D 是对已在途文本的一步生成。错开时完整编码仍在线执行，特征暂存本 worker，等下一步才消费。先测始终合、始终拆的代价；前者可能缩短图文 TTFT，后者可能降低单次文本停顿，但多推进一次 decode 会消耗时间。仅延后整个 E+P 往往只移动长停顿，也作为简单对照。

768×768 样本的 BF16 特征形状为 `[576,8192]`，单项裸张量为 9 MiB。最小原型可限制每个 worker 同时暂存一项、显式在消费或取消后释放，并测量包含激活、KV 和 allocator 的总峰值。实现上的关键是拆分后仍按原请求提交 LM token 和 KV 更新，避免把已编码但未 prefill 的状态提前记为已计算。

待验证的在线决策可以从一个小查表开始。用实际处理器网格、视觉项数估计 E，用图文 LM token、活跃 decode 数及上下文估计混合迭代 P+D，单列测量误差余量。调度点比较两个剩余时间：最紧的在途文本下一次输出期限，以及候选图文请求到首 token 的剩余时间。当前同迭代能同时满足时直接做；只有拆开才可能兼顾时拆开；两种都估计超时则记录此状态，采用明确的排队上限和保护策略，超时按失败计入。把单次完整 E 与最小 D 在串行路径下都装不进文本间隔的区间作为边界，延期只有在等得到更宽松的批次状态时才有帮助。

**最有区分度的实验是预算相同、阶段代价不同。** 先用一张固定 768×768 图，仅改变活跃 decode 数和上下文，确认相同新请求是否随 D 状态穿过门槛。再用 512×512、768×768 的单图扫描 E。若成本差只和 token 数同比变化，简单预算可能已经足够。进一步可构造图像数、总视觉占位和首步 LM token 相同的两组，例如两张 640×640 对一张 896×896 加一张 128×128。按当前 32 像素合并步长估算，两组均为 800 个占位，处理器实测及实际调度签名是纳入条件。归档 Qwen3-VL 源码由各图网格生成 attention 序列边界，面积分布会改变每张图的序列长度平方之和；实际耗时还受形状、批处理和拷贝影响。多图现有旁路只接受单项，需要单独扩展及校验。这一配对是后续识别度更高的实验，当前还没有测到成本分离。 [归档模型代码](/Users/chenhanxi/Desktop/infra/reproduction_runs/vl-encode-pilot-20261106-085428/artifacts/original_files/qwen3_vl.py:804)

因此应把研究问题从“仅按期限余量选择 E/P 是否更好”收敛到**内容风险感知的视觉 token 预算与文本/图文双期限联合控制**。D 的 A/N/S 结果仍作为调度基线和真实负载状态证据；下一阶段要在保证图像答案质量的前提下，测量减少视觉 token 是否能为图像 TTFT 与活跃文本 decode 同时释放余量。D 的正式请求输出固定 16 token，未测视觉答案质量，不能直接支持压缩安全性结论。

### 5.2 文献边界与可检验差异

SieveServe 已提出请求级视觉 token 自适应预算：用查询复杂度路由器估计问题所需视觉证据，再用稠密信息保护器降低文档、图表等内容的误剪风险；论文在八个基准上报告了准确率保留，并在高分辨率 serving workload 上报告了 TTFT 和吞吐改善。[SieveServe，EMNLP 2026](https://aclanthology.org/2026.emnlp-main.648/) 的正式 serving 评测运行在 4×A100，分别使用图像密集的 WildVision-Chat 和文本密集的 ShareGPT-4o；据此可以提出一个尚待核查的差异假设：它没有直接展示本课题拟测的“单张 GPU 上，持续文本 decode lane 与开放环图像到达并发、并逐请求联合计算两个实时 deadline slack”的同一混合负载。这个判断是对论文实验设置的推断，不是对所有相关工作的不存在性证明。另一个重要近邻 GeoPrune 专门指出常规 ViT attention 排名在 Qwen3-VL/Qwen3.5 上会变差，并提出基于视觉 encoder 输出残差能量的 engine-friendly 选择，在 vLLM 上报告了端到端延迟改善；因此下一阶段不应直接套用 attention 排名，而应把 GeoPrune 作为首选固定 token 选择基线候选，并核实其代码/版本与当前 vLLM 的兼容性。[GeoPrune，Findings of EMNLP 2026](https://aclanthology.org/2026.findings-emnlp.1913/) 高分辨率会同时增加视觉编码与 LM prefill 代价，且信息密集图像更需要保留分辨率/视觉证据，这一准确率—时延张力也得到 FastVLM 的分析支持。[FastVLM，Apple ML Research](https://pr-mlr-shield-prod.apple.com/research/fast-vision-language-models)

所以潜在贡献不能写成“首次做视觉 token 自适应”或“首次做双期限调度”。更窄的假设是：**在单卡图文混合共服务下，内容侧风险决定视觉预算下界，实时文本 slack 与图像 TTFT slack 决定可用预算和 E/P 放置；这种联合决策能否在保持稠密图像任务准确率的同时，增加双 SLO goodput。** 正式立项前需逐项复核 SieveServe、DuetInfer、TriInfer、QoServe、TEVA 等方法及代码，明确哪些算法可作为直接基线，并把复现差异写入方法。

### 5.3 具体实验设计

**硬件与系统。** 沿用 Qwen3-VL-2B-Instruct 与固定 vLLM 环境，GPU0 RTX 4090（负载 PCIe Gen4 ×16）单卡运行，GPU1（负载 PCIe Gen4 ×4）不参与；数据、权重、缓存、trace 和结果写入 `/media/chx/Win10`。先检查 SieveServe 代码是否已公开、其 QCR/DIG 能否按原定义映射到当前视觉处理链。若需改写或无法直接适配 Qwen3-VL，清楚标为“SieveServe-inspired content-only baseline”，逐项记录偏离，不声称原论文复现。

**内容质量集。** 预先固定 600 个有许可和哈希的标注样本：POPE、GQA、TextVQA、DocVQA、ChartQA 各 120 个；前两者代表相对鲁棒图像任务，后三者覆盖文字、文档与图表等稠密信息任务。对 full-token 与被压缩输入做离线配对质量评估，采用各基准官方评分；将图像级质量、视觉 token 保留率、图像分辨率、查询类型一并保存。该质量集与在线到达 trace 分离，避免重复调参。

**在线负载。** 8 个负载格：512/768 processor grid × 2/6 条 192-token 活跃文本 lane × uniform/burst 开放环图像到达。每格 5 个策略 × 12 个配对 seed，共 480 个正式 run；每个 run 60 秒预热、180 秒测量，名义 GPU 测量时间 32 小时，另加适配、质量评估、服务启停与诊断时间。运行顺序按块平衡并在下一块反序；同 seed 下各策略使用完全相同的文本、图像和到达计划。该时长只用于排程，不构成停止条件。

| 策略臂 | 定义 |
|---|---|
| N | 现有原生同一步基线 |
| A | D 阶段冻结的期限感知 N/S 动作策略，作为已测调度器基线 |
| B-fixed | 使用 GeoPrune 候选的 engine-friendly token 排名，采用固定 keep ratio；上限按独立校准集中 B-content 的平均保留 token 数匹配 |
| B-content | 使用同一 token 选择后端，仅按查询复杂度与图像稠密风险动态分配预算（尽量对照 SieveServe 的 QCR/DIG；若需改写则标为 SieveServe-inspired） |
| B-joint | 在 B-content 的安全预算范围内，再按实时 `D_slack`/`I_slack` 调整预算，并在可执行时选择 N/S |

**指标与分析。** 主指标为联合 30/55 ms SLO 图像 goodput；另报 25/45 与 40/75 ms 敏感性、文本最大间隔和图文 TTFT 的 P50/P95/P99、图文/文本完成和错误率、最长饥饿、实际视觉 token 数、E 与 P CUDA-event 时长、队列/CPU dispatch/H2D 分段时延。按 trace seed 做配对 bootstrap；答案质量另按样本配对计算区间，分开报告鲁棒与稠密信息类。实验中保留全量请求级策略输入、预算动作、实际执行 token 数与 deadline slack，以便解释收益/退化来自哪里。达到或未达到任何 SLO、准确率或资源估算都只影响结论，不跳过预注册条件或结束任务。

**实现顺序。** 先核验 GeoPrune 与 SieveServe 的作者代码/版本及与当前 Qwen3-VL、vLLM 0.33.0 的兼容性；固定数据与评分脚本，冻结 GeoPrune token ranking 及 content-only 的查询/稠密风险预算实现；再验证 token 删除后的 image grid、位置编码、KV/调度器状态与完整响应正确。冻结策略参数和 12 个 seed 后执行正式矩阵。若代码未公开或接口不能安全抽取视觉 token，则按论文方法做有记录的适配，保留失败尝试和偏离说明，不把未执行臂冒充有效结果。

## D 阶段正式结果与下一阶段方向（2026-11-09）

正式 D 矩阵和最终分析现已完成。权威输出位于 `continuation/D/results/formal-analysis-final-dedup-idfix/`：432/432 个计划运行成功，36 个条件、每格 12 个配对 seed；196 组配对比较。首 token server/API/client 顺序与 token ID 均为 46,656/46,656。最终 A 状态分区含 9,504 条决策（N=4,888、S=4,616），4,616/4,616 个 S 决策都执行了真实 E→P 拆步。108 个唯一异步 writer 元数据文件全部正常关闭，共写入 153,424,042 行，丢弃和写错误均为 0。中间分析轮次完整保留；最终报告仅使用第四轮去重后的输出。

结果显示，仅依靠 D 的期限余量在 N/S 间选择，不足以支持跨负载普遍提升联合 goodput。burst 下 A−N 在 512/2、512/6、768/2、768/6 的均值依次为 +0.00139、+0.00093、−0.00556、+0.00231 passing image/s；其中 768/2 为负，768/6 只有小幅正值。S 在 512/6 和 768/2 出现负向差。全部策略格图像和文本完成率为 1.0，主要问题表现为期限违约。D 的图文回答固定最多 16 token，且正式留出 serving 未记录 CUDA-event 视觉执行时间，因此不支持答案质量或 GPU E latency 结论。

下一阶段收敛到**单卡图文共服务下的内容风险感知视觉 token 预算与文本/图文双期限联合控制**。把 D 的 N/A/S 保留为已测调度基线；离线按 POPE、GQA、TextVQA、DocVQA、ChartQA 各 120 个样本评估质量，在线按 512/768 × 2/6 文本 lane × uniform/burst 比较 N、A、GeoPrune 固定预算、内容风险预算、内容风险加双 slack 联合预算五臂，共 480 个配对 run。任何效果大小、准确率、SLO 或资源估算不作为继续条件；详见同目录 `continuation/docs/goal-prompt-next-stage-E.txt` 与 D 报告。

文献边界：SieveServe 的 QCR/DIG 请求级视觉预算和 GeoPrune 的 engine-friendly token 排名均是直接近邻；不能声称首次提出视觉 token 剪枝或 deadline-aware serving。SieveServe 评测设置与本项目拟测的单卡活跃文本 decode + 开放环图像 + 双期限 slack 是否完全相同，是基于其论文工作负载描述的推断，仍需系统文献复核。[SieveServe](https://aclanthology.org/2026.emnlp-main.648/)；[GeoPrune](https://aclanthology.org/2026.findings-emnlp.1913/)；[FastVLM](https://pr-mlr-shield-prod.apple.com/research/fast-vision-language-models)。
