## 4. B · 实现和验证最小拆步

- 不依赖 A 的指标结果，使用同一固定基准配置实现单一固定模式 S。worker 对同一图文请求在线执行完整 E，仅推进已在途文本 D，下一迭代才让该图文请求进入 LM。特征只留在本 worker，最多一项待消费。图文在 E 步不推进 LM computed tokens 或 KV，保留原占位、M-RoPE、DeepStack、输出和终止语义。验证取消、请求结束和失败会回收暂存资源。遇到不支持的状态可以回落到原路径并显式记录，在拆步正确性统计中计为未执行拆步，所有样本仍纳入按策略分配的结果。
- 先用一张图和四路文本诊断。对照 R 与 S 的相同图像字节、processor 输出、实际视觉和语言模型步骤、图文展开输入、文本与图文输出、首次图文 P 的 KV/计算 token 计数。S 必须观测到 E 一次、E 后推进至少一步原在途 D、P 在后续步骤且消费同请求特征一次。对确定性样本比对完整 token IDs；若 batch 变化产生数值分歧，先建立未改路径的重复噪声，记录首个分歧和实际 prompt/输出长度。出现稳定臂间输出异常、重复编码、占位不匹配或缓存泄漏时，修复后重放并继续 B/C；并行完成不依赖 S 的 N/F 基线工作。必须把正确性通过与未通过的 S 结果分开，不能将未通过 S 宣称为有效拆步数据。持续诊断和重放至修复通过；若当前资源不足，安全停掉当前批次、保存证据并扩充或改排续批，然后继续。正确性未通过的 S 数据始终标为无效实现结果，但仍继续修复、重放及独立 N/F 工作。

## 5. C · 验证固定规则的失效边界

- 冻结 `512×512 / 768×768` 和 `2 / 6` 路活跃文本四个组合。输入输出长度、触发逻辑、模型、图像内容类别和原图接口保持同定义。确认实际 grid/占位、窗口完整覆盖、KV 余量和真实在途文本数。预检允许在同一原因下调整一次配置并在正式样本前记录。
- 策略 N 为同一步执行的原生 vLLM 参考，F 为用独立校准 episode 选出的最强固定原生配置（扫 prefill 节拍 1/2/3 及相容的 LM token 配额，记录实际调度）。策略 S 为始终拆步。另报可行的固定图像/视觉和 LM token 双配额 U；单图负载上若图像配额从未约束调度，直接标注 U 与 N/F 的等价条件。只要 U 的配置可行，就在计划负载中测量 U，并运行两条图文同时排队的独立探针核查其有效性；是否观察到交叉不影响是否采集。遇到可修复实现或资源问题时，调整并追加续批，直至所有可行策略与计划组合都完成；仍不支持的策略须给出代码证据和替代测量，不能用 N/F/S 结果冒充 U。
- 四个组合各三块，每策略每块 12 个 episode，块内共享输入种子和到达，平衡策略顺序，隔离调参 trace。N/F/S 共 432 个测量 episode，U 可运行时最多增至 576 个。主分析按块计算，额外给出所有有效样本和失败。正式块可报告 12 个样本的 P95，并同时呈现超时率和重复块方向。计划样本量是当前方案定义的最小完整采集量；如有效样本因失败不足，补跑直到有效样本数齐备，若为回答正确性或可复现性还需重放，也追加样本并标明用途。
- 主指标使用客户端请求级窗口内最大文本间隔与图文 TTFT。工程筛查阈值预设 **30 ms / 55 ms**，这是基于上轮数据选的实验阈值。附带 25/40 ms 文本间隔和 45/75 ms 图文 TTFT 的敏感性分析。每 episode 记录所有在途文本和图文是否同时达标，失败或超时计未达标；另报文本超时比例、图文 TTFT、完成率及引擎侧对应指标。排空回放的联合达标率用于机制筛查，开放环 goodput 留给后续方法验证。
- 所有计划组合、策略与有效 episode 完成后，再计算原“继续条件”：至少一组状态中 S 相对 N/F 将联合达标率提高 ≥10 个百分点，文本超时率下降且图文达标率下降不超过 5 个百分点；另有一组状态中 N 或 F 相对 S 的联合达标率高 ≥10 个百分点，且差异与图文 TTFT 或等待时间一致。两个现象各至少在 2/3 个配对块同方向，合并描述性差值也须过门槛。再检查是否有一个固定规则在全部四个组合与各组合最优臂相差 ≤5 个百分点。以上全部是完成采集后的研究判读标准，不是继续实验或停止实验的门槛。两个方向都成立、固定规则未覆盖且事件链有效时，列出候选在线规则所需状态与尚未覆盖负载；基线覆盖或 E 加最小 D 已持续越过文本期限时，将“当前负载下没有必要推进该切口”作为结论；其余结果记为未判定并指出最便宜的后续补证。无论是哪种结果，都先完成本方案规定的采集、分析和归档。
